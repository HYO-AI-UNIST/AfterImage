# 게임 흐름·조작 검토와 그래픽 안내서

검토일: 2026-10-19

## 기준과 결론

사용자 요청에 따라 README는 요구사항·정답의 근거로 사용하지 않았다. 클론한 원본 커밋 `2c7aada`의 실제 규칙, 클라이언트 조작, 현재 `game` 브랜치의 3D 클라이언트를 비교했다.

`lib/game.ts`, `lib/contracts.ts`, `lib/demo.ts`, `lib/room-service.ts`는 원본 커밋과 동일하다. 원본에 구현된 기본 게임 흐름과 서버의 공개·비공개 정보 경계는 유지된다. 원본 `GameAction`에서 자원을 사용하는 특수 조작은 선로 힌트(`hint`)이며, 별도의 능력 선택·스킬 명령은 없다. 문서에만 등장하는 기능을 이번 검토의 누락 항목으로 간주하지 않았다.

실제 클라이언트에서는 **배치·힌트의 키보드 대상 선택**, **힌트 선택 중 대상 선로 강조**, **높이가 낮은 화면의 개인 힌트 지도**, **화면 회전 후 GPU UI 텍스처 크기**를 보완했다. 기존 짧은 규칙 팝업은 실제 게임 규칙을 설명하는 8장 그래픽 안내서로 교체했다.

| 라운드 승리 | 첫 탈출자만 `1 + 남은 코인` 득점 | 유지. 실제 온라인 3점 득점 확인 |

| 최종 결과 | 총 7라운드, 동점 공동 우승, 방장 재시작 | 유지. 7라운드 진행과 점수 초기화 확인 |

연출 시간은 규칙의 차례 판정과 구분된다. 서버 이동은 650ms, 폭발은 1.8초, 판 전달 이벤트는 1.4초다. 3D 카메라의 차례 이동·카드 섞기는 별도의 시각 연출이며, 진행 중 로컬 보드 입력을 잠근다.

## 힌트의 사용 방식과 자원

1. 자신의 탐색 차례에 `힌트 사용 −1` 또는 `H`로 선택 모드를 켠다.
2. 버튼만 누르거나 선택을 취소하는 단계에서는 코인을 쓰지 않는다.
3. 밑변 이외의 선로를 하나 고르면 서버가 코인 1개를 차감한다. 현재 수레에 인접한 선로일 필요는 없다.
4. 답은 질문자에게만 응답하며, 개인 창의 작은 삼각형 지도에 선택한 선로를 표시한다.
5. 창을 닫으면 답과 선택 표시를 제거한다. 같은 선로를 다시 물으면 다시 1개를 쓴다.
6. 힌트는 이동·차례를 소비하지 않는다. 코인이 0이거나 남의 차례·이벤트 중이면 사용할 수 없다.
7. 코인은 새 라운드에만 3개로 보충된다. 폭발·차례 변경·판 전달에서는 보충하지 않는다.
8. 새로고침으로 힌트 답을 다시 볼 수 없다. 코인은 서버에 남아 있어 중복 복원되지 않는다.

## 이번에 보완한 클라이언트 동작

### 1. 배치·힌트의 키보드 선택

이전의 화살표 선택은 이동 가능한 분기점만 대상으로 삼았다. 힌트 모드에서는 이동 후보를 비우므로 `H → 화살표 → Enter`로 선로를 고를 수 없었다. 배치 단계도 키보드로 선로를 고를 수 없었다.

`MineWorld.keyboardTargets()`를 추가해 배치·힌트에서는 밑변을 제외한 선로, 일반 탐색에서는 이동 가능한 분기점을 반환한다. `←`·`→`로 대상을 고르고 `Enter`로 실행한다. 실제 브라우저에서 배치 및 힌트 창 진입을 확인했다.

### 2. 힌트 대상 선로 강조

선로 하이라이트가 배치 단계에만 반응하던 조건을 수정했다. 이제 힌트 선택 중 마우스를 올리거나 키보드로 선택한 선로도 밝게 표시된다. 코인 소비 전에 정확한 대상을 확인할 수 있다.

### 3. 작은 화면에서도 개인 힌트 지도 유지

기존에는 팝업 높이가 430px 미만이면 지도를 생략하고 내부 선로 ID만 표시했다. 그림 없이 실제 선로 위치를 알기 어려웠다.

현재는 짧은 가로 화면에서 답을 왼쪽, 지도를 오른쪽에 배치한다. 세로 화면도 사용 가능한 높이에 맞춰 지도를 줄이며, 지도와 안내·닫기 버튼이 겹치지 않게 간격을 확보했다.

### 4. 혼자 연습 중 안내서 읽기

안내서가 열려 있으면 로컬 봇 진행을 기다리게 했다. 온라인 경기는 계속 진행된다. 안내서 마지막 장에서 이 차이를 설명한다. 온라인 서버나 다른 참가자의 진행을 로컬 팝업 때문에 멈추지 않는다.

### 5. 화면 회전 후 GPU UI 텍스처 재할당

캔버스 해상도만 바꾸고 기존 GPU 텍스처를 재사용하면, WebGL2의 고정된 텍스처 저장 공간과 새 캔버스 크기가 달라진다. 이 때문에 실제 회전 화면에서는 텍스트와 그림이 이전 비율로 늘어나 보일 수 있었다.

HUD 캔버스의 픽셀 크기가 달라질 때 기존 텍스처의 GPU 공간을 해제하고 새 크기로 업로드하도록 수정했다. 브라우저 회전 검사에서 실제 `texStorage2D` 할당 크기와 캔버스 업로드 크기가 일치하는지도 확인한다. 화면이 매우 낮으면 안내 본문을 스크롤하며, 하단 장 이동 버튼은 고정한다.

## 그래픽 안내서

홈과 게임의 `?` 버튼 또는 `F1`로 연다. 게임 중에는 현재 단계에 맞는 장부터 시작한다. 좌우 버튼·8개 장 표시·키보드 화살표·Home/End·모바일 좌우 스와이프로 이동한다. 화면 높이가 부족하면 휠·위아래 드래그·키보드 ↑↓로 본문을 스크롤한다. 홈에서 마지막 장을 읽은 뒤 바로 연습을 시작할 수 있다.

| 장 | 주요 그림 | 설명 |
|---|---|---|
| 목표 | 다른 두 갱도와 출구로 가는 수레 | 6인, 탈출, 7라운드 누적 점수 |
| 배치 | 붉게 솟은 선로와 안전 경로 예시 | 설치·제거, 밑변, 경로 검증, 확정, 랜덤·지우기 |
| 이동 | 출발역 1–5와 수레 주변 이동 화살표 | 인접점, 양방향, 연속 이동, 화살표의 의미 |
| 관찰 | 폭발 구름과 원상태의 다음 갱도 | 공개 관찰, 지뢰 유지, 지나간 경로 비기록 |
| 힌트 | 선택 선로와 개인 답 카드, 소비한 코인 | 비용 발생 시점, 취소, 재질문, 공개 범위 |
| 판 전달 | 여섯 갱도 사이의 순환 화살표 | 실패와 차례, 전원 실패, 본인 판 제외 |
| 점수 | 조명받는 수레와 `1 + 코인 2개 = 3점` | 승점, 다음 라운드, 공동 우승 |
| 조작 | 마우스·터치·키보드와 삼각형 갱도 | 조작 키, 재접속, 온라인 진행과 연습 대기 |

그림은 실제 맵과 동일한 `level-layout.json`을 사용해 직접 생성한 PNG다. 새로운 HTML 안내 페이지나 DOM 버튼을 얹지 않고 기존 게임 캔버스 HUD 안에서 합성한다. 안내 그림의 안전 경로·지뢰는 설명용 예시이며 실제 경기의 비공개 배치를 읽지 않는다.

- 내용: `lib/mine/guide.ts`
- 렌더링: `lib/mine/hud.ts`
- 입력과 장 이동: `lib/mine/engine.ts`
- 그림 원본 생성기: `scripts/design/build_game_guide.mjs`
- 그림: `public/game/guide/`
- 재생성: `node scripts/design/build_game_ui.mjs` 또는 `node scripts/design/build_game_guide.mjs`

## 검증 범위

- 규칙·데모·방 서비스 기존 테스트 24개 통과.
- 기존 캔버스 브라우저 검사: 배치·개인 힌트·출발, 모바일 터치, 실제 API를 이용한 온라인 6인 경기, 득점, 다음 라운드, 재접속, 7라운드 종료와 재시작 통과.
- 안내서 브라우저 검사: 1440×900, 390×844, 320×568, 844×390에서 8장 이동과 화면 회전·리사이즈 확인. 568×320 회전 화면에서는 본문 스크롤도 확인.
- 키보드 배치와 힌트, 짧은 가로 화면의 개인 지도, 안내서 중 연습 봇 대기 확인.
- GPU 텍스처 할당·캔버스 업로드 크기 불일치 없음.
- 브라우저 오류·셰이더 오류·게임 에셋 요청 실패 없음.
- 타입 검사, 변경 파일 린트, 프로덕션 빌드 확인.

브라우저 검사는 로컬 Chromium에서 수행한다. 온라인 화면은 실제 호스트 캔버스를 조작하고 다른 다섯 참가자는 인증된 API 요청으로 진행한다. 여섯 대의 실기기 간 시각 동기화나 iOS/Android 하드웨어 성능까지 검증했다는 의미는 아니다.

원본 코드에도 차례 제한시간·연결 끊긴 플레이어 자동 넘기기는 없다. 온라인에서 플레이어가 접속을 끊으면 해당 자리를 복원해 계속 진행해야 한다. 이번 변경에서는 이 규칙을 유지했다.
