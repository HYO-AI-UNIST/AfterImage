# 이미지 UI · 스킬 연출 · 메모 UX 개선

기준 브랜치: `game-newrule`. 기존 3D 갱도와 main 병합 규칙을 바탕으로, 사용자 피드백 전체와 중간 피드백을 함께 반영했다.

## 반영 항목

| 요청 | 구현 |
|---|---|
| 좁거나 낮은 버튼의 에셋 변형 문제 | 액션·작은 버튼·원형 아이콘 소켓·판 선택 카드 네 종류를 별도 PNG로 제작. 각각 기본·호버·눌림·비활성 상태를 제공하고 패널 에셋을 버튼에 재사용하지 않음 |
| 버튼 크기와 내용 정렬 | 작은 버튼과 기본 액션을 구분하고 아이콘·글자 그룹의 실제 폭을 계산해 가운데 배치. 작은 크기에서도 모서리가 겹치지 않도록 9-slice 경계를 제한. 밝은 버튼의 아이콘은 어두운 잉크로 처리 |
| 스킬 선택을 필수 흐름으로 | 매 라운드 시작에 선택 창 자동 표시 → 선택 후 배치/유지 준비. 같은 라운드의 재선택은 서버와 클라이언트 모두 차단. 다음 라운드는 전원 선택 상태·자원을 초기화하고 다시 선택 |
| 라운드 전환 누락 방지 | 화면 단계뿐 아니라 방·본인·라운드 키로 배치 진입을 판정. 중간 상태를 보지 못한 재접속·느린 갱신에서도 새 라운드의 스킬 선택을 열고 배치 초안을 초기화 |
| 메모·스킬의 아이콘화 | 탐색 하단의 큰 텍스트 패널을 제거하고 렌즈·수첩·스킬 소켓 도구함으로 구성. 마우스 호버와 키보드 포커스에서 이름 표시 |
| 코인·힌트의 게임 자원 표현 | 승점 코인·힌트 결정 PNG와 숫자·충전 칸으로 표시. 공개된 판의 지뢰 수와 다른 광부의 승점도 아이콘으로 표시 |
| 스킬의 고유 색 | 잔광 호박색, 가호 청록색, 장막 보라색, 타인의 기억 분홍색, 전이 주홍색, 각인 파란색. 흰 본문과 구분해 문양·빛·입자에 사용 |
| 자신·상대 스킬의 발동 연출 | 빛 입자가 모여 문양이 떠오르고 사라지는 연출. 공개 행동인 가호·전이는 방 전체에 발동 신호만 공유. 개인 힌트·메모·훔쳐보기 결과는 공유하지 않음 |
| 스킬 창 중앙 정렬과 반복 효과 | 실제 설명 줄 수를 측정해 문양과 설명을 콘텐츠 영역의 세로 중앙에 정렬. 부유·회전 문양·빛 입자 반복. 모션 축소 환경에서는 반복 움직임 제거 |
| 불필요한 제목·문구 제거 | 제목은 스킬 이름 하나. 영문 라벨, 감성 부제, 선택 불가 안내, 중복 행동 안내 제거. 실제 효과와 수량은 유지 |
| 힌트의 게임 내 도구 연출 | 실제 선로 위에 3D 돋보기·스캔·조명·입자가 등장. 1.25초 조사 뒤 그 위치에서 결과가 튀어나오며 확인으로 제거. 배경 가림·팝업·복제 판 없이 게임 화면을 유지 |
| 팝업의 단색 배경 문제 | 금속 결·방안지·벨벳 PNG를 독립 타일로 제작. 패널을 늘려도 질감의 크기는 그대로 유지 |
| 밝은 모니터에서 드러나는 3D 경계 | 웹 배경·월드 배경·안개를 순수 검정으로 통일. 3D 재질을 월드 거리로 검정에 수렴시키고 HUD 이전에 화면 가장자리도 불투명 검정까지 페더링. 판 이동 중에는 거리 범위를 확장해 카메라 연출 유지 |
| 메모의 사용성 | 초상화로 판 주인 선택, 슬롯과 안전·지뢰·미확인 도구를 한 화면에 배치. 선로 주위 44px 폭의 가까운 구간 선택과 두 분기점 선택 모두 지원. 선택 즉시 기록, 수정·삭제·되돌리기 제공. 키보드로 선로를 고르고 Enter로 기록 가능 |

## 메모의 저장 의미

선로를 누르는 행동이 명시적인 기록 동작이다. 힌트나 훔쳐보기 결과를 자동으로 메모에 넣는 것은 아니다. 서버에는 기존의 `memo` 명령을 사용하고, 차례 밖 편집·새 라운드 초기화·작성자 비공개 경계는 유지한다. 두 분기점 방식은 첫 점과 인접점들을 크게 강조하며 연결된 두 번째 점을 선택하면 기록한다.

## 확인 기록

- 갱도 판을 유지하는 참여자까지 다음 라운드에 역할을 초기화·재선택하는 서버 회귀 검사 포함, 규칙·서비스 테스트 140개 통과.
- 기존 실제 캔버스 시나리오에서 다음 라운드 선택 창 재등장 → 재선택 → 유지 판 준비, 판 공개 범위·승점 이전·재시작을 확인했다. JavaScript·셰이더·에셋 오류 없음.
- 기록자 시나리오에서 직접 메모·남의 차례 메모·390×844 모바일 수첩을 확인했다. 빠르게 기록 후 상태를 바꿔도 요청이 직렬 처리되어 마지막 입력이 사라지지 않도록 보완했다.
- 별도 미리보기에서 넓은 선로 선택, 스킬 선택 중앙 정렬·반복 입자, 아이콘 HUD·렌즈 장치를 확인하고 위 화면을 저장했다.

TypeScript 검사, 전체 ESLint, 프로덕션 빌드도 통과했다. 빌드에는 기존의 큰 청크·vinext API 정적 분류 안내가 남아 있다. 이번 확인은 로컬 Chromium 및 데스크톱·모바일 뷰포트 기준이며 실제 모바일 하드웨어의 성능 측정은 별도다.

## 힌트 장면 후속 개선

- 돋보기는 실제 선택한 선로에 고정되며 카메라·화면 크기에 맞춰 결과 위치를 다시 계산한다. 모바일에서도 돋보기의 최소 표시 크기를 유지한다.
- 조사 → 결과 입자 확산·탄성 확대 → 확인의 순서다. 지뢰 있음·없음·판독 불가 각각의 문양과 색을 사용한다. 모션 축소에서는 조사 시간을 줄이고 이동·입자·탄성 효과를 생략한다.
- 결과가 열려 있는 동안 이동 입력과 이동 가능 표시를 막는다. 확인·차례 전환 시 장면과 임시 결과를 함께 제거한다. 비용·비공개 범위·수동 메모 규칙은 동일하다.
- 후속 작업에서는 자동 테스트를 추가하거나 실행하지 않았다. 데스크톱 및 390×844 모바일 연습 화면에서 조사·결과·확인 종료를 직접 확인했다.

## 각인·전이·입력 후속 피드백

| 항목 | 변경 |
|---|---|
| 선택 원의 호버 불일치 | 소켓 PNG의 실제 반지름 30/72와 호버·누름 이동량에 선택 테두리를 맞춤 |
| 각인 보기 창 | 우측 상단에 도움말·닫기를 나란히 배치, 하단 돌아가기 제거. 필수 선택 창의 선택 확정 흐름은 유지 |
| 전이 선택 | 이동할 지뢰를 고르면 안전 경로를 남기는 빈 선로만 주황색 점멸·흐르는 입자로 표시. 출발은 흰색, 선택 목적지는 밝은 색. 목적지 → 출발 선택 순서로 되돌리기 |
| 각인 배경 효과 | 잔광: 방사 물결, 가호: 방패 망토, 장막: 수평 물결, 기억: 교차 궤도, 전이: 반대 방향 띠, 각인: 사각 격자. 아이콘 복제·회전 방식 제거 |
| 참가자 설명 | 호버·키보드 포커스 즉시 이름·효과 툴팁 표시. 인물을 가리키는 삼각형과 박스를 하나의 외곽선·질감으로 연결 |
| 현재 차례 | 원래 모서리 모양과 같은 밝은 전용 패널과 위에서 움직이는 화살표로 표시 |
| 자원 여백 | 좌우·상단에서 안쪽으로 이동. 좁은 화면에도 별도 여백 적용 |
| 끊어진 선로 | Blender에서 연결 길이는 보존하고 위로 들린 끝부분 높이를 1.22 → 0.73으로 축소. `MINDMINER_ONLY=broken-track`으로 단독 재생성 가능 |
| 발동 문구 | 51px 배경 띠의 정확한 세로 중앙 25.5px에 배치 |
| 입력 | 첫 비동기 대기 전 포커스, 실제 입력 위치에 투명한 입력 수단 배치. 한글 조합·커서·선택 영역·Tab 이동 처리. 표시되는 필드와 글자는 캔버스에서 렌더링 |

화면: [각인 띠](polish-ribbons.png) · [각인 보기](polish-role-view.png) · [참가자 툴팁](polish-player-tooltip.png)

각인 띠의 반경을 초기 버전보다 약 29% 줄이고, 콘텐츠 영역의 실제 높이도 함께 적용해 가장자리의 딱 잘린 모양을 방지했다.

후속 확인: 실제 연습에서 두 번째 자기 차례의 전이 진입 → 지뢰 선택 → 목적지 발광 → 목적지 선택 → 되돌리기 두 단계 → 모바일에서 다시 선택·확정 → 상대 판 선택으로 복귀까지 진행했다. [전이 선로](polish-transfer-targets.png) · [모바일 전이](polish-transfer-mobile.png). 전이 중 상단·접근성 안내도 내 갱도의 지뢰 이동으로 맞췄다.

입력은 한글 이름·커서 이동·Tab으로 코드 입력 전환·대문자 변환을 직접 확인했다. 입력 중 390×844 → 390×480으로 줄여도 포커스와 실제 입력 영역이 새 필드를 따라온다. [입력 화면](polish-input-mobile.png). 이는 데스크톱 브라우저의 모바일 크기 확인이며 실제 iOS/Android 소프트 키보드 호출을 기기에서 확인한 기록은 아니다. 이번 후속 작업에서 자동 테스트는 추가·실행하지 않았다.

## 판을 유지하는 라운드의 대기 흐름

매 라운드 각인 선택 → 유지 판은 준비 자동 처리 → 다른 참가자를 기다리는 화면 → 전원 준비 시 탐색 시작. 배치를 유지하는 참여자에게는 준비 버튼·선로 편집 커서를 제공하지 않는다. 기다리는 화면에는 이번 라운드에 판을 수정하지 않는다는 설명, 참가자별 준비 표시와 진행 막대를 보여준다. 네트워크가 잠시 끊겼다가 돌아오는 경우도 준비 자동 처리를 다시 시도한다. 서버의 판 유지·준비·능력 확정 규칙과 비공개 범위는 그대로 사용한다.

## 돋보기·선로 호버·차례 패널 후속 피드백

- 돋보기 손잡이의 축을 렌즈 바깥으로 이어지는 대각선에 맞춰 금속 목과 손잡이가 하나로 연결되도록 수정했다.
- 힌트 모드의 호버 선로는 밝은 흰색, 3.6배 굵은 중심선과 넓은 빛 번짐으로 표시한다. 인접 선로로 옮기면 해당 위치를 따라간다.
- 현재 차례에는 원래 패널과 같은 꺾인 모서리의 전용 `panel-active.png`를 사용한다. 사각형 테두리와 크기가 다른 버튼 배경을 겹치던 방식은 제거했다.

UI 아틀라스와 좌표 파일에는 같은 콘텐츠 해시를 붙여, 이미지 캐시만 이전 버전으로 남아 다른 에셋을 잘못 참조하는 문제도 막았다. 해시는 UI 에셋 생성 과정에서 자동으로 갱신한다.

최종 화면 확인은 서로 다른 두 광부로 1라운드 완료 → 2라운드 각인 재선택 → 유지 판 자동 준비·대기 → 수정할 광부의 재접속·배치 → 전원 준비 후 탐색 자동 시작까지 진행했다. 유지 광부에게 준비 버튼이 나타나지 않았고, 상대 배치가 끝났을 때 추가 클릭 없이 진행됐다. [판 유지 대기 화면](polish-retained-waiting.png) · [밝은 선로 호버와 전용 차례 패널](polish-hint-hover.png) · [돋보기 손잡이](polish-hint-handle.png).
